# 幕准的工程贡献与代码导读

这个项目集成现成语音识别和 OCR，把字幕制作中通常分别处理的纠词、重点保护和排版放进同一个可检查的流程。当前贡献是工程机制，尚未验证为学术首创。

## 一条字幕如何处理

例如音频转写为“把罗拉的 rank 设置为 8”，附近画面写着 `LoRA rank = 8 alpha = 16`。

1. 语音转文字，保留原始结果，使用词时间切分字幕时段；当前没有导出逐词时间列表。画面中可核对的术语可作为识别热词，热词也写入记录。
2. 词表提出“罗拉 → LoRA”的候选。查看该字幕时段附近的 OCR 拼写依据；明确别名且画面可信时采用，近似词或证据不足时待确认。
3. 用修正后的文字找同时间的 `LoRA` 区域，扩展到同排相邻参数文字，形成重点保护区。这里使用规则关联，没有完整的视觉语义理解模型。
4. 计算修正后文字的实际字体行宽与换行，尝试位置和宽度；对重点遮挡、一般文字遮挡、过多行数、短末行和位置跳动计分。0.3 将一句字幕拆为观察时段，用带位置保持状态的动态规划选择序列，再合并相邻相同布局。
5. 展示原文、修改依据、位置和待确认项。用户改字、改时间或拖动后，重新计算布局，导出 ASS 和 MP4。

如果讲的是人名“罗拉”，而该时段屏幕只在讲 CUDA，就保留原词或等待确认。同一术语在别的场景出现，不能直接授权当前替换。

## 哪些代码体现联动

| 文件 | 用途 |
| --- | --- |
| `src/muzhun/media.py` | 实际音视频解码、OCR、语音识别、ASS 与视频合成 |
| `src/muzhun/evidence.py` | 同期画面证据、保守纠词、词与区域关联、同排参数合并 |
| `src/muzhun/layout.py` | 字体占位、时段遮挡代价、句内及连续字幕的位置稳定、限时手动保护与固定位置 |
| `src/muzhun/pipeline.py` | 修正文字和时间后重建证据与布局，保留编辑和原文 |
| `src/muzhun/evaluation.py` | 外部标注评测、随机匿名三组视频、作者单独保留对照表 |
| `skills/muzhun-subtitles/` | Agent 的处理、检查、人工复核、导出与评测工作流程 |

现成库负责语音、OCR 和渲染。本项目实现候选与证据组织、词—时间—区域关联、字幕布局评分与序列选择、编辑闭环和评测流程。没有训练新的基础模型。

## 0.3 为什么需要句内时间线

字幕 0.2–11.8 秒保持同一句话，面板在 4 秒换到底部、8 秒换回顶部。把所有帧的文字矩形合成一个集合，会把不同时刻的占位误当成同时存在；一句只选一个位置也无法利用中途出现的空位。

`_timeline` 按实际抽样帧时间、手动区域的起止时间产生观察时段。C 使用最近已观察帧的区域；开头缺少样本时使用句内第一个样本作初始估计。区域代价乘以时段持续时间，移动有额外代价。动态规划状态保存候选位置和已保持的时间；句内改变位置需已经停留至少 1.2 秒、剩余时间足够，且当前遮挡代价改善至少 1。选中序列的相同邻段合并，使静止画面仍导出一条事件。

`plans.C` 因而可能有多个相同字幕 id，但时段互不重叠，覆盖原句时间。编辑仍以原始 `cues` 为单位；SRT 从 `cues` 输出一次，ASS 从位置时段输出，复核页按 id 聚合。`samples` 保存该位置期间的观察时间和遮挡提示，估算遮挡时间按样本时段累计，避免“其中一帧有遮挡”被算为整句遮挡。

此机制没有新增视觉模型。采样通常 1 秒，长片最多约 180 个样本；快速变化可能漏检或滞后。短暂闪现可能因位置保持约束继续遮挡并标记复核，体现可读性与避让的取舍。它不是逐帧跟踪，也不保证任意视频均有空位。

生成器定义的换位面板、真实 OCR 与 MP4 可用 `scripts/verify_dynamic_demo.py` 复现。用同一 C 文字切换 static / adaptive，能单独观察时间机制的作用；报告中的最佳固定候选使用标注挑选，只供评测，不反馈给规划器。机制介绍必须与真实效果和首创结论分开。

## 如何证明联动有用

使用同一批初始字幕和样式，比较 A 固定位置、B 分别处理、C 同期证据与重点区域联动。B 是项目内对照实现，不代表现有商业工具的最佳效果。

先生成未经手动修改的三组结果，再交给不了解对应关系的朋友评分。留出没有参与调试的新视频；由熟悉内容的人独立给正确术语、重要区域和误改标注。记录准确性、遮挡和改到可发布的耗时。只有取得真实测试数据后，才能填写效果提升数字。
